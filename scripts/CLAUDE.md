# A. PDF RENDERER FORMAT SPEC (scripts/pdf_renderer.py)
# ─────────────────────────────────────────────────────────────

[DEFAULT] Resume format — generated by scripts/pdf_renderer.py (reportlab):
  DEFAULT LAYOUT: Single-column (ATS-safe, standard market format)
    Full A4 width with 40pt margins (515pt content width)
    Header: Name (22.86pt bold, dark) left + Contact lines (9pt, grey) right-aligned
    Teal rule below header for visual identity
    Sections: Profile Summary → Core Expertise + Skills → Work History → Education → Certs
    Core Expertise + Skills: full-width stacked sections, comma-separated inline
    Work history: full-width bullets — more text per line, more content per page
    Role title: Helvetica-Bold, left; Tenure: right-aligned, light grey
    Bullet dots: small filled circles, 1.1pt radius
  OPTIONAL LAYOUT: Two-column (teal sidebar — for non-ATS or explicit request only)
    Sidebar (32% width): Name → Profession → Contact → Core Expertise → Skills → Certs
    Content area (68%): Summary → Work History → Education
    Activate: pass "two_column" as 4th CLI arg or layout="two_column" in code
  Fonts:     Helvetica throughout (Regular/Bold/Oblique as specified per element)
  Colours:   Teal #0074A6, section bars #006996, body #363C49, tenure #8C8C8C
  Page size: A4
  File naming: [YOUR_NAME]_CV.pdf  (set dynamically from candidate_profile.json → contact.name)
  Certs order: configured in candidate_profile.json → certifications (keep priority certs first)
  Font sizes (pt) — all in scripts/pdf_renderer.py as FS_* constants:
    Name:                22.86pt Bold     (FS_NAME)
    Title lines:         10.23pt Regular  (FS_PROF / FS_ROLE)
    Section headers:     13.24pt Regular  (FS_RCHEAD, teal)
    Role title:          10.23pt Bold     (FS_ROLE, #525252)
    Company/date:         9.50pt Italic   (FS_CODATE)
    Bullet text:          8.50pt Regular  (FS_BULLET)
    Contact info:         9.00pt Regular  (grey)
    Expertise labels:     8.50pt Regular  (teal)
  Spacing: inter-role spaceBefore controlled in draw_work_history(); section spaceBefore in draw_section_header()
  Bullet leading: FS_BULLET * ~1.3–1.45 (set per element in build_resume())
  Page margins: 40pt left/right/top/bottom (minimum 36pt — see overflow cascade in root CLAUDE.md §A)

# 1. APIFY — LinkedIn job scraper (URL-based)
#    Script: scripts/apify_cache.py  (CachedScraper class)
#    Actor:  curious_coder/linkedin-jobs-scraper  ($1.00 / 1,000 results = $0.001/job)
#            NOTE: Python API calls use the tilde form "curious_coder~linkedin-jobs-scraper"
#            (apify_cache.py); mcp.json uses the slash form. Both refer to the same actor.
#    Input:  pre-filtered LinkedIn search URLs — time window and location filters
#            baked into the URL (f_TPR=r86400, geoId=<market_geoid>)
#    Covers: YOUR configured role searches — see SEARCHES_APIFY in run_scout.py
#            EXAMPLE (3 searches):
#              [YOUR_ROLE_1] (max 100 jobs/run)
#              [YOUR_ROLE_2] (max 100 jobs/run)
#              [YOUR_ROLE_3] (max 75 jobs/run)
#    Output: job_url, job_title, company_name, location, descriptionText,
#            postedAt (relative or ISO → converted to YYYY-MM-DD),
#            salaryInfo, id, employmentType
#    Config: needs APIFY_TOKEN in .env
#    Cost:   ~$0.001/job — varies by max_jobs configured per search
#    Cache:  data/apify_cache/ (24h TTL, key = MD5(url)[:16] + YYYY-MM-DD)
#    CLI:    python3 scripts/apify_cache.py status|clear|clear --old

[CONTEXT] URL filter status:
  WORKS:   Time window (f_TPR=r86400) — 100% compliance
           Location (geoId=<market_geoid>) — market-scoped
           f_JT=F (job type) — still honoured at URL level (~93% full-time)
           f_E=4,5 (experience level) — partially honoured
           f_WT=3,1 (work type: hybrid+onsite) — partially honoured
           Note: f_JT/f_E/f_WT removed from LinkedIn UI (AI search beta)
           but still active as URL params — kept for noise reduction.
  KEYWORDS: Single precise keyword per URL (e.g. "Lead Data Analyst").
           Actor scrapes without browser session — LinkedIn's AI search semantic
           layer is not engaged. Single keywords return clean targeted results.
           Tested and rejected: boolean OR (too loose), space-separated multi-title
           (AND condition → 0 results), natural language AI-search format (0 results).
  MISSING FIELDS: workplaceType → work_type (always empty); applyUrl →
           apply_url_hint (always empty); salary (frequently empty — expected).
           work_mode is extracted from JD text by Claude Pass 2 instead.
  FIELD USAGE NOTE: seniority_level, is_easy_apply, work_type look unused in code,
           but score_jobs._build_user_prompt passes ALL non-null job fields to Claude
           Pass 2 via raw_meta — they ARE scoring inputs. Do not remove them from
           apify_cache._normalize.

[CONTEXT] Apify actor selection rationale:
  curious_coder/linkedin-jobs-scraper chosen because:
  - URL-based input: LinkedIn geoId and time filter applied before scraping
  - $0.001/job — cost-efficient for daily pipeline runs
  - High adoption and rating on Apify marketplace
  - No LinkedIn cookies or login required
  - Returns unique LinkedIn-sourced data

[RULE] When calling the Apify actor, input is:
  {"urls": ["<pre-filtered-linkedin-url>"], "count": max_jobs}
  (plain string URL in the list, NOT a {"url": "..."} object)
  Per-URL max_jobs are defined in SEARCHES_APIFY 3-tuples in run_scout.py
